# HASI.TJ: сброс базы и обновление каталога

## Что добавлено

- `npm run catalog:sync` — загружает товары и категории из публичного WooCommerce Store API `https://hasi.tj/wp-json/wc/store/v1/`, обновляет цены, описания, SKU, ссылки на товары и оригинальные URL изображений. Удаляет товары, которых больше нет в источнике, предварительно удалив связанные складские ссылки. История заказов хранится как снимки названий/цен и не очищается при синхронизации каталога.
- `npm run catalog:sync:local` — то же самое, но строго для локальной БД `data/hasi.db`, даже если в `.env.local` указаны переменные Turso.
- `npm run seed` — повторная синхронизация каталога с hasi.tj.
- `npm run dev:local` — сначала синхронизирует локальный каталог, затем запускает Next.js dev-сервер.
- При первой инициализации пустой базы `lib/db/seed.ts` пытается загрузить реальный каталог и использует локальный seed только как fallback, если внешний API недоступен.
- `npm run db:reset` — очищает заказы, заявки/сообщения, обычные аккаунты, дилерские данные, расчёты, складские движения и пользовательские корзины/избранное. Сохраняет товары, категории, настройки и центральный склад; создаёт/обновляет одного администратора.

## ВАЖНО: сброс удаляет данные

Сначала сделайте резервную копию. Сброс не запускается автоматически при `npm run dev:local`.

Если `TURSO_DATABASE_URL` и `TURSO_AUTH_TOKEN` заданы, команда сброса остановится, пока вы явно не подтвердите работу с удалённой базой:

```bash
CONFIRM_REMOTE_DB_RESET=YES npm run db:reset
```

Без Turso сброс работает с локальной `data/hasi.db`. Если схема ещё не создана, сначала запустите приложение один раз, чтобы таблицы инициализировались.

## Примечания о каталоге

Цены и изображения берутся из опубликованных данных сайта в момент синхронизации. Если сайт недоступен или его публичный WooCommerce Store API отключён, команда завершается ошибкой и не начинает очистку устаревших товаров до успешного получения списка. Не запускайте sync по production базе без проверки `TURSO_DATABASE_URL`.

`npm run dev:local` задаёт `HASI_LOCAL_DB=1`, поэтому Next.js использует `data/hasi.db` даже если `.env.local` содержит Turso credentials. Обычные `npm run dev` и `npm start` по-прежнему используют Turso, когда заданы обе переменные подключения.

### Если синхронизация сообщает `fetch failed`

Скрипт повторяет сетевой запрос три раза и теперь показывает URL и сетевую причину (например, `ENOTFOUND`, `ECONNRESET`, `CERT_*`). Проверь соединение:

```bash
node -e "fetch('https://hasi.tj/wp-json/wc/store/v1/products?per_page=1').then(async r => console.log('HTTP', r.status, (await r.text()).slice(0,300))).catch(e => console.error(e.message, e.cause?.code, e.cause?.message))"
```

Если официальный сайт/API не открывается из этой сети, синхронизация не может выдумывать актуальные товары: подключись к доступной сети или задай правильный публичный адрес через `HASI_CATALOG_URL` в `.env.local`. База не очищается, пока каталог не получен успешно.
